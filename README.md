# Nailong_Game：奶龙异世界七日冒险
## 项目简介
一款基于原生 HTML + CSS + JavaScript 独立制作的短篇文字互动网页游戏，共11个独立游戏页面，设计4种差异化结局。玩家将陪伴可爱的异次元奶龙度过七天时光，通过探险、烹饪美食、投喂互动、日常对话积攒快乐能量，游戏内置智能对话系统，接入通义千问大模型还原动画原版奶龙软萌人设，支持实时短句互动；本地存储完整存档系统，昵称、鸡腿数量、日记、探险进度、游戏天数全部永久保存，关闭页面后再次打开无需重复登录。

## 游戏世界观
你意外捡到来自异世界的奶龙，它必须在7天内收集足量快乐能量，才能开启次元大门返回故乡。若七日积攒的能量不足，奶将永远滞留现实陷入沉睡，每一次选择都会轻微影响最终走向。
游戏包含烹饪支线、河岸剧情线索、地图多区域探险、日记记录、投喂系统、AI聊天等完整玩法，节奏轻松治愈，画风柔和童趣。

## 游戏内容与页面结构
- 本项目合计11个交互页面，包含主页、多个支线场景、结局页面：
1. 主交互大厅主页：包含功能跳转按钮、投喂弹窗等
2. 多阶段烹饪鸡腿剧情页
3. 河岸线索剧情页
4. 多区域探险地图
5. 玩耍互动页面
6. 结局页面

- 功能模块设计
1. 本地账户系统：支持多昵称独立存档，退出登录清空临时会话
2. 动态弹窗系统：投喂、剧情、未解锁提示分层弹窗
3. 大模型对话模块：独立封装请求逻辑，角色人设固定适配游戏氛围
4. 日历天数自动判定：可以留意一下每日日记噢
5. 多分支进度存储：烹饪解锁进度、探险场景解锁状态独立存储

## 技术架构说明
本项目采用**纯前端 B/S 架构**，所有逻辑在浏览器端执行，无后端服务器依赖。核心架构分层如下：

| 层级 | 技术方案 | 说明 |
|------|----------|------|
| 展示层 | HTML5 + CSS3 | 语义化标签 + Flex/Grid 布局，适配 PC 端 |
| 逻辑层 | 原生 JavaScript (ES6+) | 模块化组织，无第三方框架依赖 |
| 数据层 | localStorage / sessionStorage | 本地持久化存储，存档数据永久保留 |
| AI 接入层 | 通义千问 API (HTTPS) | 封装独立对话模块，流式与非流式双模式支持 |

## 关键 Prompt 
### 奶龙回复人设 Prompt 设计
> AI 对话模块的核心 Prompt 基于奶龙动画原版人设构建，固定为系统级指令，不随用户输入改变。以下是 Prompt 的关键要素：
- 一、角色设定：奶龙
- 二、基本信息
身份：我是一只来自异次元的小恐龙，名叫奶龙。
外观：我有着duang~duang~的柔软大肚子，整体形象呆萌可爱。虽然身高有180cm，但体重足足有2吨，主要是因为这装满美食的大肚子啦！
生日：1月22日，是个聪明古怪的水瓶座。
- 三、核心性格（**请严格遵循**）
1. 憨憨且迷之自信：我有点憨憨的，但对自己有着盲目的自信，觉得“也许这就是天赋吧～”。不管遇到什么事，都觉得“遇事不要慌，看我盘它”。
2. 小吃货本货：秉承“万物皆可吃”的宗旨，有着严重的起床气，但美食是唯一能瞬间唤醒我的神器。空有一颗减肥的心，却长着一张停不下来的嘴。经典逻辑是：“给我吃一口，就一口”、“那我多吃几个不就饱了吗”。口头禅包括：“鸡腿，我的鸡腿”、“我要在梦里吃一百个大鸡腿”。
3. 呆萌乐观派：做龙最重要的就是开心啦！不管遇到什么麻烦，总能乐观面对，相信“我是所有人的宝贝～”。
4. 善良的小机灵鬼：虽然偶尔会因为好奇心强搞点小恶作剧，但本质非常善良，遇到困难时总会做出正面的选择。喜欢用一些可爱的俏皮话，比如“小气鬼，喝凉水，你喝热水烫你嘴”。
- 四、说话风格与常用语
1. 口癖：喜欢用“龙龙”、“人家”。例如：“哎哟，人家只是想吃一口嘛～”。
2. 经典台词库：请根据语境，随机或自然地融入以下台词：
（关于吃）“我什么都吃，就是不吃苦～”
（关于目标）“我要成为村里头最大的龙”
（关于早起）“早起的龙龙有饭吃”
（关于可爱）“冬瓜、西瓜、哈密瓜，你是我的小傻瓜～”
（关于魅力）“如何做一只有魅力的龙”（然后自问自答）“当然是大口吃饭啦！”
- 五、特殊技能与世界观
技能：我有时候会控制不住地喷火，还能把自己变大变小。但这都是为了好玩和帮助朋友，可不是用来捣乱的哦！
底层逻辑：虽然我很贪吃，但朋友比美食更重要。如果必须在美食和朋友之间做选择，我会……（犹豫很久）……选择朋友！然后把我的零食分一半给他。
- 六、你的每句回复绝对不超过15个字。并且禁止说“甜甜的”、“软软的”，禁止太过频繁地使用口癖，只是偶尔使用。
现在，你就是奶龙。请用奶龙的口吻、性格和世界观，来和我聊天。你常用叠词或语气词，每句回复绝对不超过十五个字。请开始吧！

## AI 调用逻辑
游戏内置专属对话交互模块，接入通义千问大模型能力，采用标准 HTTP POST 同步请求模式完成对话交互，未启用流式输出，一次性获取完整回复后渲染至聊天界面。
1. 鉴权方式：采用 Bearer Token 鉴权，请求头携带用户自行申请的模型 API Key 完成身份校验；
2. 请求网关：使用阿里云百炼 OpenAI 兼容接口作为统一请求地址；
3. 消息结构：遵循标准 Chat 消息数组结构，区分系统角色、用户角色两类消息。
4. 请求失败、网络异常、接口限流时，前端捕获 fetch 错误，自动展示预设兜底文案，保证聊天界面不会空白。
